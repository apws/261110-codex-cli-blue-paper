== Local settings

The selected profile is:

[source,json]
----
{
  "enabled": true,
  "paper": "#D9EBFF",
  "ink": "#000000",
  "emphasis_ink": "#A64200",
  "hint_ink": "#164E82",
  "cursor": "terminal",
  "cursor_text": "auto",
  "user_text_bold": false
}
----

This keeps the accepted pale-blue paper and normal black text, uses a readable burnt orange for styled elements, and dark blue for the floating backscroll hint. Optional fields default to `auto`, except `cursor` defaults to `terminal` and ordinary bold defaults to `false`; the explicit local orange/blue choices are preferences rather than universal defaults.

Edit `~/.config/codex-blue/colors.json`, then restart codex-blue and resume the conversation. Subsequent profile edits need no compilation. Existing three-key profiles remain valid. The launcher validates hex colors, keyword choices and boolean values, reports unknown keys, and preserves inherited context/configuration. Explicit `CODEX_BLUE_PAPER*` environment overrides retain precedence.

`emphasis_ink` controls text elements, plugin mentions and applicable key-label emphasis inside the input surface. `hint_ink` controls Back to bottom / New activity on its actual custom paper. With `auto`, both follow corrected ordinary ink. `user_text_bold` can be enabled for editable/submitted ordinary text and the placeholder, independently of terminal font family or size.

== Cursor and the character beneath it

At Falken's separate request, `~/.config/kitty/kitty.conf` now specifies:

[source,conf]
----
cursor #008000
cursor_text_color background
----

Falken reported that the regular-green cursor was visible and later that the character beneath it had improved, before the new executable was installed. These observations concern Kitty's terminal settings. `cursor_text_color background` draws that character using the underlying cell background: pale blue over this composer, and the respective background over other terminal content. Kitty configuration can be reloaded using Ctrl+Shift+F5, independently of a Codex frontend restart.

With the selected JSON `cursor: "terminal"`, codex-blue emits no cursor-color override; both cursor colors remain Kitty-owned. The JSON `cursor_text` field is only used when an application cursor override is enabled. To try that mode, set `cursor` to `auto` or a hex color. Then `cursor_text` accepts `auto` or a requested hex foreground. The draft's contrast correction can darken a very light requested cursor fill against pale paper; terminal mode preserves Kitty's chosen green exactly.

Application cursor overrides are limited to custom-paper cells. They reset when the cursor leaves those cells, is hidden, or the terminal is handed back during exit, panic cleanup, external-program use or Ctrl+Z suspension. Kitty supports independently requested cursor fill/text through its documented OSC 21 protocol; the xterm-compatible fallback changes fill only. Unknown terminals and detected screen/tmux sessions retain terminal control. Forced termination cannot execute cleanup.

The relevant terminal references are https://sw.kovidgoyal.net/kitty/conf/#opt-kitty.cursor[Kitty cursor configuration], https://sw.kovidgoyal.net/kitty/color-stack/[Kitty color controls] and https://invisible-island.net/xterm/ctlseqs/ctlseqs.html[xterm control sequences]. No remote-control permissions or broader Kitty theme/font settings were enabled.

== Rendering behavior and boundaries

The composer resolves independent named/RGB foregrounds against its actual custom paper. It keeps semantic accents readable, removes terminal-dependent dimming inside its custom-paper cells, and preserves content, wrapping, selection reversal and underline. Different-background overlays and externally owned graphics cells are excluded. An interactive footer consequently no longer dims the blue composer cells. Status hints outside the blue area keep their normal styling.

The optional user-text weight and element emphasis apply to user history too. This does not provide a full palette for every rich asynchronous-reply or spoken-message presentation. The generated design mock-up is a color proposal, not a captured running UI. The original initial-release previews and acceptance evidence remain preserved separately.
